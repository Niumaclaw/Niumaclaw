# NiumaClaw MVP Commercialization Checklist

本清单用于把 NiumaClaw 从可用 Demo 推进到可试用、可交付、可收费的 MVP 商业化版本。MVP 的目标不是一次性做完整企业平台，而是让第一个真实团队能在 30 分钟内完成安装、连接本机 Agent、派发真实任务、看到结果、追踪日志，并愿意继续试用或付费。

## 产品定位

- [ ] 对外一句话定位明确：面向一人公司和小团队的 AI 员工调度台。
- [ ] 核心卖点明确：网页派工、本机执行、过程可见、结果可追踪、权限可控。
- [ ] 首个目标用户明确：有开发/运营/内容任务的小团队负责人，而不是泛泛所有企业。
- [ ] 首个核心场景明确：老板在网页派任务，桌面 Agent 在本机用 Codex、Claude Code 或 Hermes 完成，并回传结果。
- [ ] 对外避免承诺完全自动化，强调人可控、可审核、可追踪。

## P0: MVP 必须完成

### 1. 安装与首次启动

- [ ] macOS 提供真正可打开的 `.dmg` 安装包。
- [ ] macOS 应用完成 Developer ID 签名和 notarization，避免默认被系统拦截。
- [x] Windows 提供真正安装器，例如 `.exe` 或 `.msi`，不要只给压缩包。（EXE 首次打开自安装到本机并创建快捷方式）
- [x] 下载页清楚显示平台、版本号、文件大小、更新时间。
- [ ] 下载链接可稳定触发，支持断点或至少避免浏览器无响应。
- [ ] 桌面端首次启动显示连接向导，而不是只显示日志窗口。
- [x] 首次启动可一键检测服务器连通、工作区路径、Codex CLI、Claude Code、Hermes、Git、Node、Python。
- [x] 检测失败时给出可执行修复建议，例如安装路径、命令、权限设置。

### 2. 桌面 Agent 可用性

- [ ] 启动 Agent 按钮状态清楚：未配置、可启动、运行中、连接失败。
- [ ] Agent 运行时能自动注册到服务器并显示在线。
- [ ] 服务器重启、网络中断后 Agent 能自动重连。
- [ ] 任务队列不丢任务，重复领取有保护。
- [ ] 每个 Agent 绑定固定节点 ID，并允许用户修改显示名称。
- [ ] Agent 能读取 GUI 环境下缺失的常见 CLI 路径。
- [ ] Agent 执行前能确认工作区存在，不存在时自动创建或提示选择。
- [ ] Agent 退出前能通知服务器离线。

### 3. 派工到回传闭环

- [ ] 网页端可选择一个本机 Runner 员工并派发任务。
- [ ] 桌面端能收到任务并显示任务内容。
- [ ] Codex、Claude Code、Hermes 至少一个适配器完整跑通。
- [ ] 任务状态完整流转：待领取、运行中、成功、失败、取消、超时。
- [ ] 桌面端执行完成后，网页端工作日志必须展示最终回复。
- [ ] 网页端最近运行必须展示任务状态、耗时、失败原因和执行时间。
- [ ] 用户可重新执行失败任务。
- [ ] 用户可取消运行中的任务。
- [ ] 同一个员工连续派多个任务时按队列执行，不互相覆盖。

### 4. 工作日志与可追踪性

- [x] 工作日志默认展示最终答案，不把 CLI 元信息当主内容。
- [ ] 技术详情可展开查看 stdout、stderr、命令、退出码、token 用量。
- [ ] 每条任务都有唯一运行 ID。
- [ ] 每条任务记录显示派发人、执行节点、模型/适配器、工作区、开始和结束时间。
- [x] 失败任务必须有可读错误，例如 command not found、timeout、permission denied。
- [ ] 工作日志支持复制结果。
- [ ] 工作日志支持导出 Markdown。
- [ ] 任务产物文件有索引入口，例如生成的代码、文档、截图、报告。

### 5. 安全与权限底线

- [ ] 每个 Agent 只能访问配置的工作区。
- [ ] 默认不允许 Agent 执行工作区外的 destructive 操作。
- [ ] 高风险操作需要人工确认，例如删除大量文件、部署生产环境、推送 Git、执行数据库变更。
- [ ] 日志中自动隐藏常见密钥、token、cookie、私钥片段。
- [ ] 服务器和桌面端通信必须有节点 token 或等价认证。
- [ ] 节点 token 可重置。
- [ ] 用户退出团队或删除节点后，该节点不能继续领任务。
- [ ] 管理员能看到节点最后心跳和来源 IP。

### 6. 账号、团队与授权

- [ ] 支持稳定登录，不依赖临时本地状态。
- [ ] 至少支持一个组织下多名员工/节点。
- [ ] 区分管理员和普通成员。
- [ ] 管理员可以添加、禁用、删除 Agent 节点。
- [ ] MVP 阶段支持手动开通授权码或许可证。
- [ ] 授权限制清楚：可用节点数、团队人数、有效期。
- [ ] 授权过期时保留历史数据，只限制新任务或新节点。

### 7. 可靠性与运维

- [ ] 服务端有健康检查接口。
- [ ] 服务端有基础错误日志和启动日志。
- [ ] 数据库有备份策略。
- [ ] Agent 任务表有索引，避免任务多了以后工作日志变慢。
- [ ] 前端接口失败时显示错误提示，不静默无响应。
- [ ] 关键路径有超时控制。
- [ ] 线上版本号可在后台或接口看到。
- [ ] 发布流程可回滚到上一版本。

### 8. 对外试用包装

- [ ] 官网首屏说明产品能解决什么问题，而不是只展示趣味界面。
- [ ] 提供 60 秒 Demo 视频。
- [ ] 提供 5 分钟快速开始文档。
- [ ] 提供 macOS 和 Windows 安装教程。
- [ ] 提供 Codex CLI 安装与登录说明。
- [ ] 提供常见问题：打不开、无法连接、命令找不到、下载慢、任务无回复。
- [ ] 提供反馈入口：邮箱、微信群、表单或工单。
- [ ] 提供明确价格预期，即使 MVP 阶段先人工开通。

## P1: 首批付费试用增强

- [ ] 任务模板：修 Bug、写页面、生成文档、代码审查、运营文案、日报周报。
- [ ] Agent 能力标签：编码、文档、测试、部署、运营。
- [ ] 任务前置确认：目标、输入、验收标准、是否允许修改文件。
- [ ] 任务完成后支持老板评价：满意、不满意、继续修改。
- [ ] 支持 GitHub 仓库连接和 PR 链接回填。
- [ ] 支持项目看板和 Agent 运行记录绑定。
- [ ] 支持按团队统计任务数、成功率、平均耗时、失败原因。
- [ ] 支持预算和 token 成本估算。
- [ ] 支持自动更新桌面客户端。
- [ ] 支持私有部署安装脚本。

## P2: 暂缓到 MVP 之后

- [ ] 复杂多 Agent 自动规划。
- [ ] Agent 市场和插件市场。
- [ ] 完整在线支付和发票系统。
- [ ] 企业 SSO。
- [ ] 手机 App。
- [ ] 大规模多租户权限矩阵。
- [ ] 自研模型训练或微调平台。
- [ ] 通用 RPA 自动化平台。

## 上线验收标准

- [ ] 新用户在 30 分钟内完成注册、下载、安装、连接 Agent。
- [ ] 新用户无需开发人员协助即可派发第一条任务。
- [ ] 第一条任务完成后，网页端能看到清楚结果。
- [ ] 任意失败任务都能看到明确失败原因。
- [ ] macOS 和 Windows 各完成 3 次全新安装测试。
- [ ] 同一节点连续执行 10 条任务，没有丢任务或状态错乱。
- [ ] 服务端重启后，桌面端能在 60 秒内自动恢复连接。
- [ ] 下载、安装、连接、派工、回传、查看日志这 6 个环节都有文档或 UI 提示。
- [ ] 至少 3 个非开发背景用户完成试用并能复述产品价值。
- [ ] 至少 1 个真实团队愿意继续使用或进入付费沟通。
