# NiumaClaw B 站宣发视频脚本

## 视频定位

- 视频时长：60 秒左右
- 目标观众：AI 工具玩家、独立开发者、项目经理、想用 Agent 自动做项目的人
- 核心记忆点：NiumaClaw 不是聊天框，而是一家能按阶段交付的“牛马公司”
- 视频风格：轻松、吐槽、工程感、带一点 B 站梗感，但不要过度鬼畜

## 可直接录制的旁白稿

你有没有试过，让 AI 做个官网，结果它直接跳到测试报告？

我也遇到过。所以我做了一个更像项目团队的 Agent 系统，叫 NiumaClaw。

在这里，你不是跟一个聊天框许愿，而是给一群员工派活。比如做一个官网，它必须先写 PRD，再出页面原型，再做 UI/UX 视觉规范，然后才允许进入前端开发、测试报告和本地链接。

每一步都要有交付物。PRD 没完成，原型不开门；开发没完成，测试不会提前跑。模型偶尔空返回也没关系，如果目标文件已经生成，系统会自动识别交付物，继续推进下一阶段。

员工节点离线时，它也不会只告诉你失败了，而是直接给出原因、重试、重启和打开日志。

你还可以做周期任务，让团队每天自己巡检项目、检查异常、汇报进度。

如果你也想让 AI 不只是聊天，而是真的像团队一样按流程交付项目，来 GitHub 试试 NiumaClaw。

## 封面方案

- 主标题：我开了一家 AI 牛马公司
- 副标题：PRD -> 原型 -> 开发 -> 测试，全流程交付
- 画面：左侧放 `office_bull_01.png`，右侧放项目看板截图，底部加 GitHub/NiumaClaw
- 颜色：沿用项目浅棕背景，按钮和进度条用蓝绿强调，避免大面积纯紫

## 剪辑注意

- 开头 3 秒一定要用痛点，不要先讲项目背景。
- 员工图片要多次出现，形成“牛马员工真的在上班”的记忆点。
- 每个功能点只讲一句，不展开技术细节。
- 项目看板镜头要突出“阶段门禁”和“交付物”，这是和普通 Agent 聊天工具最大的差异。
- 收尾一定给 GitHub 地址，方便 B 站观众直接搜索。
