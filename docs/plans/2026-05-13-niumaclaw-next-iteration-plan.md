# NiumaClaw 下一步开发计划：简单好用版

日期：2026-05-13

## 目标

下一版不追求“更多功能”，而是把 NiumaClaw 打磨成一个普通用户能顺利跑通的本地 AI 员工工作台：

> 用户输入一句目标，系统自动按阶段推进，最终给出交付总结、交付物和本地预览链接。

核心体验指标：

- 首次打开后 3 次点击内能启动一个示例任务。
- 创建任务时不需要理解节点、模型、治理、目标链等内部概念。
- 每个任务卡片默认只展示当前阶段、交付总结、交付物和下一步动作。
- 多阶段任务不能跳阶段：前置交付物不存在时，不允许提前测试、部署或生成最终报告。
- Agent 离线或模型空返回时，系统给出可执行修复动作，而不是只显示报错。

## 产品定位

NiumaClaw 不做 Dify/Flowise 式的大型工作流平台，短期聚焦：

- 本地优先：能在用户电脑上跑起来。
- 任务优先：用户关心事情有没有做完，不关心底层编排细节。
- 交付优先：每个任务必须沉淀文件、链接、报告或明确结论。
- 简单优先：默认给简单模式，专家信息折叠到详情里。

## v0.2.0 版本主题

版本名：`Easy Mission Beta`

一句话目标：

> 让“做一个官网”这种长链路任务，从一句话需求稳定跑到本地可访问页面和测试报告。

## 开发范围

### 1. 极简任务入口

目标：把用户从“管理一堆员工”引导到“交代一件事”。

交付物：

- 首页新增一个主输入框：`你想让团队完成什么？`
- 内置任务模板：
  - 做官网
  - README/GitHub 包装
  - 竞品调研
  - Bug 修复
  - 内容运营方案
  - 视频脚本
- 模板选择后自动生成阶段计划、推荐员工和默认验收标准。

建议实现：

- 前端：`NiumaClaw.Team/index.html`
- 后端接口：
  - `GET /api/task-templates`
  - `POST /api/tasks/from-template`
- 配置文件：`task_templates.json`

验收标准：

- 用户不填写节点地址也能创建示例任务。
- 官网模板创建后自动生成 6 个阶段：PRD、原型、UI/UX、开发、测试、本地链接。
- 任务创建后的第一屏只显示任务标题、当前阶段和下一步按钮。

### 2. 交付物中心

目标：替代复杂看板默认视图，让用户一眼看到“做了什么、文件在哪、下一步是什么”。

交付物：

- 项目看板默认展示简版任务卡。
- 每张任务卡只展示：
  - 当前阶段
  - 进度
  - 交付总结
  - 交付物列表
  - 主操作按钮
- 执行历史、治理建议、目标链、上下文、运行日志默认折叠。

建议实现：

- 前端新增 `renderSimpleTaskCard(task)`。
- 保留现有复杂信息，但迁移到：
  - `详情`
  - `执行历史`
  - `治理与诊断`
  - `上下文`

验收标准：

- 一个任务卡在 1366px 宽度下首屏内能完整看完核心信息。
- 任务完成后，卡片上必须能看到最终交付物入口。
- 复杂字段不再默认铺满页面。

### 3. 多阶段任务门禁

目标：解决“PRD 还没写，测试报告已经出来”的核心问题。

交付物：

- 阶段状态机：
  - `pending`
  - `running`
  - `review_required`
  - `done`
  - `blocked`
- 每个阶段定义必须存在的交付物。
- 未满足前置阶段时，后续阶段不能启动。

官网任务阶段契约：

| 阶段 | 必须交付物 | 通过条件 |
| --- | --- | --- |
| PRD | `docs/prd.md` | 包含目标用户、核心卖点、页面范围、验收标准 |
| 原型 | `docs/prototype.md` 或 `docs/wireframe.md` | 包含页面结构、模块布局、交互说明 |
| UI/UX | `docs/ui-spec.md` | 包含颜色、字体、组件、响应式规则 |
| 开发 | `index.html` 或前端工程文件 | 本地服务能访问 |
| 测试 | `docs/test-report.md` | 包含测试环境、用例、结果、问题 |
| 本地链接 | `docs/local-service.md` | 包含启动命令和本地 URL |

建议实现：

- 新增阶段定义结构：`stage_contracts.json`
- 后端新增校验函数：
  - `CanStartStage(task, stage)`
  - `ValidateStageDeliverables(task, stage)`
  - `AdvanceStage(task, nextStage)`
- 所有自动推进入口都必须走阶段校验。

验收标准：

- 删除 `docs/prd.md` 后，原型阶段不能启动。
- 开发文件不存在时，测试阶段不能启动。
- 如果模型空返回但目标交付物已存在，系统自动生成完成摘要并推进下一阶段。

### 4. 节点医生

目标：让员工离线问题变成可修复问题。

交付物：

- 员工卡片离线时展示明确原因：
  - 端口无响应
  - `/api/config` 失败
  - `/api/status` 失败
  - 模型列表读取失败
  - 节点忙碌超时
- 提供操作：
  - 重新检测
  - 一键重启节点
  - 打开工作日志
  - 编辑节点地址

建议实现：

- 后端接口：
  - `GET /api/nodes/diagnose`
  - `POST /api/nodes/{name}/restart`
- 前端新增 `renderNodeHealthBadge(employee, diagnosis)`。
- 对 Hermes/LocalNode 区分不同启动命令。

验收标准：

- 节点离线时，不再只显示“节点离线服务未启动”。
- 至少能对本地节点给出端口、接口和最近成功时间。
- 点击“重新检测”后不刷新整页也能更新状态。

### 5. 一键示例任务

目标：让新用户第一次打开就能看到 NiumaClaw 的完整能力。

交付物：

- 首页按钮：`运行示例任务`
- 示例任务：`做一个介绍 NiumaClaw 的官网`
- 自动跑完整链路：
  - PRD
  - 原型
  - UI/UX
  - 开发
  - 测试报告
  - 本地测试链接

建议实现：

- 示例任务可使用轻量 mock 模式，保证没有模型时也能演示流程。
- 示例输出写入独立目录，避免污染真实工作区。
- 示例任务完成后弹出交付摘要。

验收标准：

- 全新用户无需配置真实 Agent，也能看到完整演示流程。
- 示例任务结束后至少产生 5 个文件和 1 个本地预览链接。
- README 中可以用该示例录制 30-60 秒 Demo。

### 6. 简单模式 / 专家模式

目标：降低界面噪音，同时保留高级调试能力。

交付物：

- 默认简单模式：
  - 团队状态
  - 任务入口
  - 当前任务
  - 交付物
  - 员工是否可用
- 专家模式：
  - 模型
  - token
  - 心跳
  - 目标链
  - 治理建议
  - 原始运行日志
  - 审计记录

建议实现：

- 前端增加全局状态：`uiMode = simple | expert`
- 将复杂面板统一包进 `details` 或折叠面板。
- 本地保存用户偏好。

验收标准：

- 默认打开是简单模式。
- 专家模式切换后能看到现有调试信息。
- 简单模式下项目看板不再出现大段治理文本。

## 实施顺序

### 第 1 周：界面减法和任务入口

- 重构首页顶部布局，突出任务输入框。
- 增加任务模板配置。
- 新增简单任务卡片。
- 项目看板默认切换为交付物中心。

产出：

- `task_templates.json`
- 极简任务创建入口
- 简版项目看板

### 第 2 周：阶段门禁和交付物校验

- 建立阶段契约。
- 所有多阶段任务接入状态机。
- 修复提前测试、提前完成、模型空返回导致阻塞的问题。

产出：

- `stage_contracts.json`
- 阶段推进校验逻辑
- 官网任务完整阶段流

### 第 3 周：节点医生和恢复体验

- 增加节点诊断接口。
- 员工离线卡片改成可操作诊断卡。
- 增加本地节点重启入口。

产出：

- 节点诊断 API
- 一键重新检测
- 节点恢复操作

### 第 4 周：示例任务和发布包装

- 做一键示例任务。
- 补 README 演示路径。
- 录制新版 Demo。
- 整理 v0.2.0 Release。

产出：

- 完整示例任务
- Demo 视频素材
- v0.2.0 发布说明

## Issue 拆分建议

P0：

- 简版项目看板：默认只展示阶段、交付总结、交付物。
- 官网任务阶段门禁：未完成 PRD 不能进入原型。
- 模型空返回兜底：交付物存在时自动完成阶段。
- 节点医生：离线原因和重新检测。

P1：

- 一句话任务入口。
- 任务模板系统。
- 一键示例任务。
- 简单模式/专家模式。

P2：

- 更漂亮的首次启动向导。
- 交付物下载打包。
- Demo 录制和 README 动图。
- 英文文档同步。

## 不做事项

下一版暂不做：

- 工作流画布。
- 插件市场。
- 多租户公司管理。
- 企业权限系统。
- 云端部署平台。
- 移动端适配优先级优化。

这些能力有价值，但会稀释当前最重要的目标：让用户第一次用就能跑通。

## 风险与对策

| 风险 | 对策 |
| --- | --- |
| 阶段校验过硬导致任务卡住 | 提供“人工确认完成”入口，但必须写入原因 |
| 示例任务依赖模型不稳定 | 提供 mock/demo 模式 |
| 简单模式隐藏太多调试信息 | 保留专家模式，一键展开 |
| 节点重启命令平台差异大 | 第一版只保证 Windows 本地节点 |
| 交付物路径混乱 | 统一任务工作目录和产物索引 |

## 最小可交付版本

如果只做一版最小 v0.2，范围压缩为：

1. 项目看板简化为交付物中心。
2. 官网任务阶段门禁。
3. 节点离线诊断。
4. 一键示例任务。

这四项完成后，NiumaClaw 的核心体验会从“能管理 Agent”变成“能把任务做完并交付”。
